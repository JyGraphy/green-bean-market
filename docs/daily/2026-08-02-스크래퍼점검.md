## 3. 발견 사항 (모두 '주의' — 위반 아님)

### 3-1. 모모스·커피리브레가 `to_products()`를 우회해 `clean_name()`을 못 탄다

`scrapers/scraper_momos.py:201`
```python
items = [it for it in items if not is_non_bean(it['name'])]  # 비생두 제외
```

`common.to_products`는 `is_non_bean(clean_name(it['name']))`로 **정제 후** 판정하고, 이어서
`clean_name()`·`name_is_soldout()`을 적용합니다 (`common.py:200-208`). 두 스크래퍼는 원문 이름을
그대로 넘겨서 `[재입고]` 같은 상태 라벨이 상품명에 남습니다.

실데이터 확인:
```
모모스커피 | [재입고] Brazil Baba Blend Red Catuai Natural
모모스커피 | [재입고] Baba Blend Red Catuai Pulped Natural
```

규칙 4는 자체 필터로 충족하므로 위반은 아니나, "단일 진실 공급원" 원칙에서 이탈한 상태입니다.

**조치**: 두 파일의 로컬 `to_products()`를 `common.to_products(...)` + `common.update_json()`으로 대체.

### 3-2. 사용되지 않는 구버전 `guess_process`가 남아 있다

`scraper_momos.py:54`, `scraper_coffeelibre.py:48`에 로컬 `guess_process()`가 정의돼 있으나,
실제 호출부는 `from common import ... guess_process as _cgp` (`scraper_momos.py:200`,
`scraper_coffeelibre.py:166`)라 **데드 코드**입니다.

리턴값 자체는 `data.js`의 `PROC_CLS` 키와 충돌하지 않아 규칙 5 위반은 아닙니다. 다만 구버전이라
`세미워시`·`디카페인`·`레포사도` 등이 빠져 있어, 누군가 `_cgp`를 지우고 로컬 함수를 쓰면
즉시 분류 품질이 퇴행합니다.

로컬 `ORIGIN_MAP`/`REGION_MAP`(`scraper_momos.py:21-46`, `scraper_coffeelibre.py:23-40`)도
실제로 쓰이는데, `common` 버전에 있는 세인트헬레나·동티모르·태국·라오스·미얀마·'르와다' 오타 보정이
빠져 있습니다. 커피리브레 쪽은 영문 산지명도 전부 없습니다.

**조치**: 로컬 `guess_process` 삭제, `guess_origin`도 `common` 것을 import.

### 3-3. `abs_url()`을 거치지 않는 URL 조립 2곳

`scrapers/scraper_cobeans.py:32`
```python
url = BASE + '/shop/' + href if href.startswith('detail') else (abs_url(BASE, href))
```
`scrapers/scraper_blessbean.py:29`
```python
url = BASE + f'/shop/{code}'
```

두 경우 모두 `BASE`가 `https://`로 시작하므로 **결과는 절대 URL이며 규칙 3 위반이 아닙니다**
(실데이터에서도 상대경로 0건 확인). 다만 규칙 3이 요구하는 단일 경로(`abs_url`)를 우회하고 있어,
사이트가 URL 구조를 바꾸면 여기만 조용히 깨집니다. cobeans 쪽은 삼항 연산자 우선순위가 헷갈리기
쉬운 형태이기도 합니다.

**조치**: 양쪽 모두 `abs_url(BASE + '/shop/', href)` 형태로 통일.

### 3-4. 아얀투 `parse_v2` 폴백이 카드 전체 텍스트를 상품명으로 캡처한다

`scrapers/scraper_ayantu.py:36`
```python
name = a.get_text(' ', strip=True)
```

`parse()`가 빈 결과면 `parse_v2()`로 넘어가는데(line 62), 이때 가격·할인율·배지가 상품명에
딸려 들어옵니다. `common.clean_name`의 꼬리 제거 정규식(`common.py:96`)은
`NEW|BEST|MD|품절|SOLD OUT`만 알아서 `SALE`이나 `10%`가 끼면 무력화됩니다.

실데이터 4건:
```
id=793 | 생두 2025 타데세 낸세보 Natural 19,000원 10% 17,100원 SALE SOLDOUT
id=597 | 생두 2025 문타샤 Anaerobic 2022 CoE 1위 68,800원 10% 61,920원 SALE BEST MD
id=600 | 생두 2024 문타샤 Peaberry Washed ... 68,000원 10% 61,200원 SALE BEST MD
id=596 | 생두 2025 문타샤 Peaberry Natural ... 68,800원 10% 61,920원 SALE
```

덧붙여 **아얀투 20개 상품 전부가 `origin='알수없음'`**입니다 (상품명에 '에티오피아'가 없어
`guess_origin` 실패). 검사 6항목에는 없지만 사이트 필터 품질에 직접 영향이 있습니다.

### 3-5. `scripts/scrape-falcon.js`에 `START_ID + i` 순차 ID 부여가 남아 있다

```js
const START_ID = 850; // 기존 최대 ID(845) 이후부터 시작
...
const rows = products.map((p, i) => { const id = START_ID + i; ...
```

규칙 2가 명시적으로 금지한 패턴입니다. 다만 이 스크립트는 **파이프라인에 연결돼 있지 않고**
(`run_all.py`는 `scraper_falcon.py`를 실행), 결과를 `scripts/falcon-output.sql`로만 떨어뜨리는
수동 도구입니다. 실제 ID 최댓값은 이미 1417까지 올라와 있어 `START_ID=850` 주석 자체가
낡았습니다. 누군가 이 스크립트를 다시 쓰면 중복 ID가 생깁니다.

**조치**: 삭제하거나, 파일 상단에 "폐기 — `scrapers/scraper_falcon.py` 사용" 주석 추가.

### 3-6. `run_all.py`에 스크래퍼별 타임아웃이 없다

`scrapers/run_all.py:56`
```python
result = subprocess.run([sys.executable, path], capture_output=False)
```

프로세스 분리 덕분에 예외·`SystemExit(1)` 격리(규칙 6)는 완벽합니다 — 실패한 store만 에러 목록에
쌓이고 나머지는 계속 진행되며, `scrape.yml`의 `continue-on-error` + 마지막 표면화 스텝이 규칙 9와
정확히 일치합니다. 다만 `timeout=` 인자가 없어, 한 사이트가 응답을 무한정 끄는 경우 잡 전체가
GitHub Actions 한도까지 매달립니다. 블레스빈은 상품마다 상세페이지를 도는 구조라 특히
취약합니다 (`scraper_blessbean.py:84-91`).
