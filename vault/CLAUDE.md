# 생두마켓 세컨드 브레인 — 정리 규칙

이 볼트는 **옵시디언으로 열어 읽는 지식 창고**다. AI 직원들이 모은 것이 여기에 쌓이고,
정리된 결과만 `wiki/`에 남는다. **읽는 것은 옵시디언에서 — 읽기만 하는 데 AI를 부르지 않는다.**

## 구조

```
vault/
├── raw/          IN  — 원본. 수집한 그대로. 수정 금지.
│   ├── coe/              COE 옥션 리포트 (날짜별)
│   ├── stores/           신규 공급사 발굴 보고 (날짜별)
│   ├── qa/               검수 보고서 (qa_report.py 자동 생성)
│   ├── papers/           논문 정리본
│   └── roast-profiles/   로스팅 프로파일 출처·데이터
└── wiki/         OUT — 정리된 지식. 주제당 파일 하나. 항상 최신 상태.
    └── index.md          전체 목차 (scripts/build_wiki_index.py 자동 생성)
```

## 규칙

1. **주제 하나당 파일 하나.** `wiki/`는 날짜로 나누지 않는다. 새 정보가 오면 기존 주제 파일을 **갱신**한다.
2. **raw는 절대 수정하지 않는다.** 원본은 증거다. 틀린 게 있으면 wiki에서 바로잡고 raw는 그대로 둔다.
3. **출처는 raw 파일명으로 표기한다.** wiki의 모든 주장은 `[[2026-08-02-옥션리포트]]` 형태로
   근거가 되는 raw 문서에 링크한다. 링크 없는 주장은 쓰지 않는다.
4. **혼자 떠도는 파일 금지.** 새 wiki 문서는 반드시 `index.md`에서 도달 가능해야 한다.
   (`build_wiki_index.py`가 자동으로 목차를 다시 만든다.)
5. **wiki는 짧게.** 주제당 A4 2장 이내. 길어지면 세부는 raw에 두고 wiki는 결론과 링크만 남긴다.
6. **미확인은 미확인으로.** raw에서 "미확인"인 값은 wiki에서도 미확인이다. 추측으로 메우지 않는다.

## 정리 작업 지시 (사장님이 쓰는 한 줄)

> `vault/raw`에 있는 것 전부 읽어. `vault/CLAUDE.md` 규칙대로 `vault/wiki`로 정리해.
> 주제당 파일 하나씩, 기존 문서는 갱신해.

이 한 줄이면 된다. 단, **토큰을 아끼려면** 새로 들어온 raw 문서만 지정해서 시키는 게 좋다:

> `vault/raw/coe/2026-08-04-*` 읽고 `wiki/coe-옥션.md` 갱신해.

## 목차 갱신 (토큰 0)

```bash
python3 scripts/build_wiki_index.py
```

wiki 문서의 제목·수정일·raw 링크 수를 읽어 `wiki/index.md`를 다시 만든다. AI 토큰 0.
