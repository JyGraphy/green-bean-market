# 📥 사진 수집 대기열

`scripts/fetch_photos.py --queue` 가 이 파일을 읽어 **위키미디어 공용**에서 자유 라이선스
사진을 받아 `vault/assets/photos/` 에 넣는다. GitHub Actions("리서치 자료 수집")에서 실행된다.

```
- [ ] <키> | <Commons 검색어> | <메모> | <제목·설명에 반드시 있어야 할 정규식(선택)>
```

- 키는 파일명이 된다 — `<키>-1.jpg`, `<키>-2.jpg` …
- 자유 라이선스(CC0/PD/CC BY/CC BY-SA)만 통과한다. ND·NC·불명은 버린다.
- 성공한 줄만 `[x]` 로 체크된다. 실패는 남아서 다음에 다시 시도된다.
- **4번째 칸(require)을 꼭 쓸 것.** 검색어만으로는 피사체가 보장되지 않는다
  (2026-10-17 1차 수집: "Coffea arabica Caturra" → 바나나 사진·프레스코화,
  "Coffea eugenioides" → 분포 지도). require 를 주면 파일 제목·설명에 그 말이
  있는 것만 받는다. 그래도 **종 오인은 남으므로 받은 뒤 사람이 눈으로 본다.**

## 폐기한 수집 (2026-10-17 1차)

사람이 눈으로 보고 버린 것들. **왜 버렸는지 남겨서 같은 실수를 반복하지 않는다.**

| 키 | 받아온 것 | 문제 |
|---|---|---|
| caturra-plant | `Banana_caturra.JPG` | 바나나. "caturra"가 다른 뜻으로도 쓰인다 |
| caturra-plant | 팔라초 스키파노이아 프레스코 | 그림. 검색어가 엉뚱하게 걸렸다 |
| eugenioides | 분포 지도 PNG | 사진이 아니다 |
| arabica-tree | *Coffea canephora* 사진 2장 | 종이 다르다 — 검색어에 arabica 를 넣어도 보장 안 됨 |
| bourbon-plant | laurina 농장 / 일반 농장 전경 | 부르봉 수형이 아니다 (사진 자체는 쓸 만해 다른 키로 재등록) |
| peaberry | 로스팅 원두 더미 / 체리 가지 | 피베리 특징이 안 보인다 |
| arabica-leaf | 실내 화분 사진 | 품질이 낮다 |

→ 이 경험으로 require 필터와 사진 아님 차단을 넣었다. 그래도 **받은 뒤 눈으로 보는
단계는 생략하지 않는다.** 자동 수집이 보장하는 것은 라이선스까지다.
