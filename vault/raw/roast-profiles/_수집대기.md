# 📥 로스터기 자료 수집 대기열

`scripts/roast_machine_fetch.py --queue` 가 이 파일의 `- [ ] <기기키> <URL>` 줄을 읽어
자료 원본을 `vault/raw/roast-profiles/sources/` 에 저장한다.
GitHub Actions("리서치 자료 수집", 매주 월요일)에서 논문·옥션 수집과 **같이** 실행된다.

## 왜 이렇게 하나

로스팅 AI는 파인튜닝 모델이 아니라 **판독 규칙 프롬프트**다.
그래서 기기 자료를 모으는 것만으로는 아무 일도 일어나지 않고, 그 자료를 읽고
`machines/<기기>.md` 의 `## 판독 규칙` 으로 옮겨야 비로소 학습이 된다.

```
리서치 중 기기 자료 발견 → 이 대기열에 한 줄 추가
   → 다음 리서치 실행이 원본을 받아 sources/ 에 저장   ← roast_machine_fetch.py
   → roast-profile-collector 가 읽고 machines/<기기>.md 판독 규칙 작성
   → build_roast_knowledge.py 가 프롬프트에 주입              ← 학습
   → deploy-functions.yml 이 실서비스 자동 배포
```

Claude Code 세션은 허용목록 정책 때문에 제조사 사이트가 403으로 막힌다.
그래서 **URL 을 여기 적어두고 Actions 러너가 받아오게** 한다.

## 쓰는 법

```
- [ ] <기기키> <URL>  <메모>
```

- `<기기키>` 는 `machines/<기기키>.md` 의 파일명과 **똑같이** 쓴다.
- 표(사양표)는 마크다운 표로 보존된다 — 열원·프로브·배치용량 사양이 핵심 자료다.
- 받아진 원본은 **수정하지 않는다**(raw 규칙). 정리는 `machines/` 에서 한다.

## 우선순위 — 실측 검증이 안 된 기기

실제 차트로 판독을 테스트하지 못해 `verified: no` 로 남아 있다.
