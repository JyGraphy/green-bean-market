## 🎯 이 작업의 목적

로스터기마다 **열원 방식이 다르다** — 드럼(전도) · 열풍(대류) · 할로겐(복사) · 하이브리드.
그래서 온도 곡선 모양, 터닝포인트 위치, 총 로스팅 시간, ROR 거동이 전부 다르다.

사용자가 **로스터기를 입력하면 그 기기에 맞는 그래프와 결과값**이 나와야 한다.
그래야 판독 오차가 줄고, 로스터가 나중에 피드백할 때 정확해진다.

## 학습의 실체 (중요)

`supabase/functions/analyze-roast/index.ts` 의 로스팅 AI는 **파인튜닝 모델이 아니다.**
Claude 비전 모델 + **판독 규칙 프롬프트** 구조다. 즉 이 AI의 지식 = 그 프롬프트다.

**프로파일을 모으기만 해서는 AI가 하나도 똑똑해지지 않는다.**
모은 지식을 기기별 판독 규칙으로 바꿔 프롬프트에 주입해야 학습이 된다.

```bash
python3 scripts/build_roast_knowledge.py --report   # ← 이게 '학습' 단계
```

**실서비스 반영(배포)** — `.github/workflows/deploy-functions.yml` 이 자동 처리한다.
`supabase/functions/` 가 변경되어 main에 푸시되면 자동 배포된다.
(저장소 시크릿 `SUPABASE_ACCESS_TOKEN` 등록 필요. 없으면 조용히 건너뛴다.)

수동으로 하려면 맥 터미널에서:
```bash
brew install supabase/tap/supabase   # 최초 1회
supabase login                       # 최초 1회
supabase functions deploy analyze-roast --project-ref txnpbzukavajwbmggpfk
```

## 학습 루프 ① — 외부 지식 (수동 트리거)

1. `roast-profile-collector`가 기기별 특성을 신뢰 출처에서 수집
2. `vault/raw/roast-profiles/machines/<기기>.md` 에 기록 (열원·프로브·시간·판독규칙)
3. `build_roast_knowledge.py` 로 AI 프롬프트에 주입 ← **학습**
4. Supabase 자동 배포 → 실서비스 반영

## 학습 루프 ② — 실사용 피드백 (완전 자동) ⭐

**로스터가 사이트를 쓸수록 AI가 정확해지는 구조.** 매주 화요일 자동 실행.

```
로스터가 차트 업로드 → AI 판독
   → 사용자가 마법사에서 값 수정 → AI 원본(ai_raw)과 최종값이 함께 저장
   → roast_feedback.py 가 그 차이를 기기별로 집계          ← 오답 노트
   → 반복 패턴을 판독 규칙 문장으로 변환해 machines/*.md 갱신
   → build_roast_knowledge.py 가 프롬프트에 주입           ← 학습
   → deploy-functions.yml 이 실서비스 자동 배포
```

**핵심 아이디어**: 사용자가 AI 값을 고친 그 수정분이 곧 정답 라벨이다.
지금까지는 최종값만 저장하고 AI 원본을 버려서 이 신호가 사라지고 있었다.

집계 항목: 기기 오인 · 투입/배출온도 오차 · 이벤트 시점 오차(TP·건조종료·1·2차크랙·배출) ·
총 시간 오차. 표본 3건 미만인 기기는 우연을 규칙으로 굳히지 않기 위해 건너뛴다.

| 워크플로 | 주기 | 하는 일 |
|---|---|---|
| `roast-learning.yml` | 매주 화 09:00 KST | 피드백 집계 → 규칙 갱신 → 프롬프트 주입 |
| `deploy-functions.yml` | 프롬프트 변경 시 | 실서비스 자동 배포 |

**필요 시크릿**: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`
(없으면 조용히 건너뛴다 — 등록하면 자동 학습이 켜진다.)

**개인정보**: 집계에 필요한 컬럼만 조회한다. user_id·생두명·메모는 읽지 않는다.

**DB 준비**: `roasting-migration-ai-feedback.sql` 을 Supabase SQL Editor에서 한 번 실행해야
`ai_raw` 등 컬럼이 생긴다. 실행 전까지는 신호가 쌓이지 않는다.

## 알아낸 것 (논문 기반)

### 색도는 하나의 곡선을 따른다

프로파일·산지와 **무관하게** 로스팅 색 변화가 단일 곡선으로 수렴한다는 연구.
→ 색도만으로는 프로파일을 역추정할 수 없다는 뜻이므로, 학습 데이터에는
**색도 외에 시간축 정보가 반드시 필요**하다. 자세히는 [[2026-08-02-보편색곡선]].

### 산미는 1차 크랙에서 정점

적정산도(TA)가 로스팅 진행에 따라 **1차 크랙 부근에서 최대**가 되고 이후 감소한다.
→ 1차 크랙 시점(FC)이 프로파일 데이터에서 가장 중요한 이벤트 마커다. 자세히는 [[2026-08-02-적정산도]].

## 수집 스키마

`raw/roast-profiles/` 에 프로파일 1건 = JSON 1개. 필수 필드:

```
source_url, source_type, collected_at, license_note,
machine, batch_size_g, bean{origin,process,variety},
curve[{t_sec, temp_c, ror}], events{charge,dry_end,first_crack,drop}, notes
```

- 그래프 이미지에서 읽은 값은 `source_type`에 `+chart-read`를 붙이고 판독 오차를 notes에 명시
- 단위 변환(°F→°C)을 했다면 반드시 기록
